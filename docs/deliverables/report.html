1. Abstract

This report presents the design, implementation, and evaluation of HomeBot, a fully local, privacy-first AI desktop assistant built with Electron, React, and TypeScript. Unlike cloud-dependent assistants such as ChatGPT or Copilot, HomeBot runs open-source language models on the user's own hardware via Ollama, ensuring that no personal data leaves the machine unless the user explicitly opts in to a cloud provider.

HomeBot integrates 85+ system-level tools spanning filesystem operations, code execution, web search, email, calendar, vision, RAG (Retrieval-Augmented Generation), and voice interaction. A 9-layer security model governs all tool execution, enforcing path whitelists, command blocklists, SSRF protection, and mandatory user confirmation for destructive actions. The application features seven distinct modes—Dashboard, Chat, Automation, Image Generation, Documents, Web, and Quiz—providing a comprehensive desktop AI experience.

The project comprises 241 TypeScript source files, 131 test files, and 512 git commits developed iteratively over 13 weeks. Evaluation demonstrates that HomeBot delivers sub-second deterministic tool responses and streaming LLM output within 1–3 seconds on consumer-grade hardware, while maintaining strict privacy guarantees.

2. Introduction

2.1 Background

The rapid advancement of large language models (LLMs) has transformed how users interact with computers. Services like OpenAI's ChatGPT, Google's Gemini, and Anthropic's Claude have demonstrated that AI assistants can handle complex tasks from writing code to analysing documents. However, these services share a fundamental limitation: they are cloud-hosted, requiring constant internet connectivity and transmitting user data to external servers.

For privacy-conscious users, professionals handling sensitive data, or individuals in bandwidth-constrained environments, this dependency on cloud infrastructure is a significant barrier. The emergence of open-source models—notably Meta's Llama, Alibaba's Qwen, and Mistral AI's models—combined with inference frameworks like Ollama, has made local AI inference feasible on consumer hardware for the first time.

2.2 Problem Statement

No existing desktop application combines the following properties in a single package:

  • Fully local AI inference with no mandatory cloud dependency
  • Deep system-level tool integration (filesystem, terminal, email, calendar, code execution)
  • Multi-modal interaction (text, voice, vision, documents)
  • Comprehensive security model governing all tool execution
  • Rich desktop UI with streaming responses, conversation persistence, and multiple application modes

2.3 Project Objectives

The primary objective of this project is to design and implement a desktop AI assistant that:

  1. Runs entirely on local hardware with zero mandatory cloud dependencies
  2. Provides 80+ tools across 10+ categories for real system-level task execution
  3. Implements a multi-layered security model preventing misuse of system tools
  4. Delivers a polished, professional desktop UI with streaming responses
  5. Supports extensibility through optional cloud LLM providers and n8n workflow orchestration

2.4 Scope

HomeBot targets Windows desktop environments (Windows 10/11) as the primary platform. While the Electron framework supports cross-platform builds, macOS and Linux packaging are deferred to future work. The application is designed for single-user operation on personal computers.

3. Literature Review

3.1 Local LLM Inference

The feasibility of running LLMs on consumer hardware has improved dramatically since 2023. Ollama (ollama.com) provides a lightweight runtime for quantised models, enabling 7B-parameter models to run at interactive speeds on GPUs with as little as 4 GB VRAM. Research by Dettmers et al. (2022) on quantisation techniques (GPTQ, GGML) demonstrated that 4-bit quantised models retain 95%+ of their full-precision accuracy while reducing memory requirements by 75%.

Qwen 2.5 (Alibaba, 2024) represents the current generation of efficient open-source models, offering strong reasoning capabilities at the 7B parameter scale. For vision tasks, Moondream (vikhyatk, 2024) provides lightweight image understanding at under 2 GB VRAM.

3.2 Desktop AI Assistants

Existing desktop AI tools fall into two categories: cloud-dependent chat interfaces (ChatGPT Desktop, Claude Desktop) that wrap web APIs in native shells, and developer-oriented tools (GitHub Copilot, Cursor) focused narrowly on code completion. Neither category provides general-purpose system tool access with privacy guarantees. Open-source projects like Jan.ai and LM Studio offer local model inference but lack tool execution capabilities.

3.3 Agentic AI Systems

The concept of AI agents—systems that can plan, execute tools, and iterate toward goals—has been explored extensively in research (Yao et al., 2023, "ReAct: Synergizing Reasoning and Acting"). HomeBot's agentic loop draws on this paradigm, allowing the LLM to chain multiple tool calls across rounds while maintaining safety constraints through recursion caps and confirmation gates.

3.4 Electron Application Security

Electron applications face unique security challenges due to their dual-process architecture. The Electron security guidelines (electronjs.org/docs/security) recommend enabling contextIsolation, disabling nodeIntegration, and minimising the preload API surface. HomeBot follows all recommended practices and extends them with application-specific safety layers.

5. System Architecture

5.1 High-Level Overview

HomeBot is a multi-process Electron application with three distinct execution contexts:

User Desktop | +-- HomeBot Electron Application | | | +-- Renderer Process (React + TypeScript) | | - Chat interface with streaming responses | | - Dashboard, Quiz, Automation, Image, Docs, Web modes | | - Voice conversation with neural TTS | | - Settings, analytics, conversation sidebar | | | +-- Preload Bridge (contextBridge API) | | - Typed API surface: 60+ IPC channels | | - Zero direct Node.js access from renderer | | | +-- Main Process (Node.js) | - Message router (deterministic + LLM routing) | - Agentic loop engine (multi-step tool chaining) | - Tool executor (85+ tools, 29 modules) | - Config manager (encrypted secrets, 5s cache) | - Scheduler, auto-updater, window manager | +-- Ollama (localhost:11434) | - qwen2.5:7b (chat), moondream (vision) | - nomic-embed-text (RAG embeddings) | +-- n8n (localhost:5678, optional) | - Workflow orchestration via Docker | - Webhook-authenticated communication | +-- Local Storage - Conversations, settings, quiz progress - RAG index, memory store, automation configs - Encrypted API keys via safeStorage

5.2 Process Communication

The renderer and main processes communicate exclusively through Electron's IPC mechanism, mediated by a typed preload bridge. The preload script (widget/src/preload/index.ts) exposes a window.electron object with 60+ methods, each mapped to a named IPC channel. This architecture ensures:

  • Context isolation: The renderer cannot access Node.js APIs or the filesystem directly
  • Type safety: The ElectronAPI interface in shared/types.ts defines the complete contract
  • Security: Only explicitly exposed methods are callable from the UI

5.3 Message Routing

When a user sends a message, the routing pipeline processes it through multiple stages:

  1. Document expansion: If the message includes file attachments, their content is extracted and injected into the prompt
  2. Deterministic routing: Regex patterns match common intents (weather, time, web search, NBA) and execute tools directly without LLM overhead
  3. Multi-step detection: Compound requests trigger the agentic loop, which injects an agentic system prompt and allows the LLM to plan and chain tools autonomously
  4. LLM streaming: Open-ended queries are forwarded to Ollama with the full tool set, streaming tokens back to the renderer in real time
  5. Tool execution: When the LLM returns a tool_call, the router checks permissions, runs safety validation, executes the tool, and returns results to the LLM for synthesis

6. Implementation

6.1 Tool System

HomeBot's tool system is the core differentiator from cloud-based assistants. Each tool is a TypeScript module exporting a definition (JSON Schema parameters, permissions, category) and a handler function. All 85+ tools are registered at startup and made available to the LLM through Ollama's function-calling API.

6.2 Agentic Loop Engine

For complex, multi-step requests, HomeBot employs an agentic loop that allows the LLM to autonomously plan and execute tool chains. The engine:

  • Detects compound requests via heuristic analysis
  • Injects a specialised agentic system prompt with planning instructions
  • Streams step-progress indicators to the UI during execution
  • Caps execution at MAX_AGENTIC_ROUNDS = 6 outer rounds and MAX_TOOL_ROUNDS = 10 inner tool calls per round

6.3 RAG (Retrieval-Augmented Generation)

HomeBot implements a local RAG pipeline that allows users to index personal documents and query them through natural conversation:

  • Documents are chunked and indexed using TF-IDF weighting
  • The index is persisted to rag-index.json in the user data directory
  • Queries retrieve the top-k relevant chunks and inject them as context for the LLM
  • The Quiz Mode integrates with RAG to generate questions from the user's own study notes

6.4 Voice Conversation

The voice subsystem provides hands-free interaction through three components:

  • Speech recognition: Windows SAPI (Speech API) via a PowerShell bridge in the main process
  • Text-to-speech: Microsoft Edge neural TTS (msedge-tts package) using the en-US-AvaNeural voice for natural, female speech output
  • Continuous mode: After speaking a response, HomeBot automatically re-activates the microphone, enabling fluid conversation without manual button presses

6.5 Streaming UI

Chat responses are displayed token-by-token in real time using a streaming architecture:

  • The main process streams tokens from Ollama via chunked HTTP responses
  • Each chunk is forwarded to the renderer through an IPC event channel
  • The renderer appends tokens to the message display with smooth scroll management
  • Users can cancel mid-stream or retry failed messages

6.6 Automation Center

The Automation Center allows users to create reusable workflows using plain English instructions:

  • Automations store natural language instructions that are executed through HomeBot's full tool chain
  • Trigger modes: manual execution or scheduled intervals (15 minutes to 24 hours)
  • Five built-in templates: Summarise Clipboard, Morning Briefing, Code Review Helper, Daily Study Notes, System Health Check
  • Background timer engine re-syncs every 60 seconds to handle CRUD changes

6.7 Quiz Mode

An interactive learning tool with:

  • 12 programming topics (JavaScript, Python, TypeScript, React, SQL, Data Structures, etc.)
  • 3 difficulty levels with configurable question counts
  • Persistent progress tracking: per-topic accuracy, streaks, best streak, letter grades
  • RAG Study Buddy mode: generates quiz questions from the user's own indexed documents

HomeBot implements a defence-in-depth security model with nine distinct layers, recognising that an AI assistant with system tool access requires rigorous safety controls:

7.1 Permission System

Tools requiring elevated access (filesystem writes, terminal commands, email sending) declare requiredPermissions in their definitions. When invoked, the executor checks the user's permission grants. If a permission has not been granted, a modal dialog presents three options: Allow Once, Always Allow, or Cancel. Permission state is persisted across sessions.

7.2 Encrypted Secrets

API keys and sensitive configuration values are encrypted at rest using Electron's safeStorage API, which delegates to the operating system's credential store (Windows DPAPI). Keys are decrypted transparently in memory when needed and never written to disk in plaintext.

10. Discussion

10.1 Strengths

Privacy by architecture: HomeBot's privacy guarantees are structural, not policy-based. Because all inference runs locally, there is no data exfiltration vector for core functionality. This is a fundamentally stronger guarantee than cloud providers' privacy policies.

Tool depth: With 85+ tools spanning 10 categories, HomeBot goes far beyond a chat wrapper. Users can manage files, run code, search the web, send emails, and query their own documents—all through natural conversation. The agentic loop enables multi-step workflows that would otherwise require multiple applications.

Security rigour: The 9-layer security model demonstrates that AI tool execution can be made safe for desktop use. Each layer addresses a distinct attack surface, from SSRF to command injection to LLM hallucination-driven tool abuse.

10.2 Limitations

Model quality: Local 7B models, while capable, cannot match the reasoning quality of cloud-hosted models like GPT-4 or Claude. HomeBot mitigates this through optional cloud routing for complex queries, but the baseline local experience is limited by hardware constraints.

Platform scope: The current release targets Windows only. While Electron is cross-platform, several tools (Windows SAPI for speech recognition, PowerShell-based system utilities) have Windows-specific implementations that would require porting.

RAG limitations: The TF-IDF-based RAG engine is effective for keyword-matching retrieval but lacks the semantic understanding of embedding-based approaches. For large document collections, retrieval accuracy may degrade.

10.3 Lessons Learned

The iterative development approach proved essential for managing complexity. Early investment in the typed IPC bridge and tool registration pattern paid dividends as the tool count grew—adding new tools required only a definition and handler function, with no changes to the routing or permission infrastructure.

The 9-layer security model emerged incrementally as new attack surfaces were identified during development. This reactive approach, while effective, suggests that a formal threat model early in the project would have produced a more systematic security design.

11. Conclusion and Future Work

11.1 Conclusion

HomeBot demonstrates that a fully local, privacy-first AI desktop assistant is viable on modern consumer hardware. By combining open-source language models, a comprehensive tool system, and a multi-layered security model, the project delivers functionality comparable to cloud-based assistants without requiring internet connectivity or transmitting personal data to external servers.

The application's seven modes, 85+ tools, voice interaction, RAG engine, and agentic capabilities make it a versatile desktop companion suitable for productivity, learning, and development tasks. The 9-layer security model provides confidence that system tool access can be made safe for end users.

11.2 Future Work

  • Cross-platform packaging: macOS and Linux builds with platform-native speech and system tool implementations
  • Plugin marketplace: A community-driven system for distributing and installing third-party tool modules
  • Embedding-based RAG: Replace TF-IDF with vector embeddings for improved semantic retrieval on large document collections
  • Multi-modal input: Combine image, voice, and text in a single turn for richer interaction
  • Local fine-tuning: Pipeline for personalising the base model on the user's conversation history and preferences
  • Collaborative mode: Shared conversation spaces for team use cases
  • Mobile companion: Lightweight mobile client that communicates with the desktop instance over local network
